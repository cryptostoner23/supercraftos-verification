# SuperCraftOS iPad transfer

Transfer `YourApp.swiftpm.zip` over SFTP, unzip it in the iPad Files app, and open `YourApp.swiftpm` with Swift Playgrounds. The manifest targets iOS/iPadOS 17, supports iPad and iPhone, and includes the SwiftUI app entry point. No third-party Swift package downloads are required.

All sibling `.swift` files are canonical raw UTF-8/LF exports. The archive includes identical copies of every source file plus `App.swift` and `Package.swift`; import the complete bundle, not just two files.

The application opens without a backend. The particle/canvas views, JSON formatter, Base64 tools, persistent notebook and sharing work locally. Runtime controls, model-generated workflows, approvals and service evidence require the existing SuperCraftOS service. Open Connection and paste the complete private HTTPS access link, including its `#access-key` fragment, or enter the HTTPS origin and access key separately. The app stores the origin in settings and the credential in the device Keychain. It sends bearer authentication and a refreshed control token for mutations, refuses redirects, and verifies task download checksums. Provider keys stay on the server. The HTTPS proxy routes to the authenticated gateway and preserves the public Host/Origin; only the gateway forwards to the loopback application.

The visuals include wiring, constellation, vortex and lattice modes, canvas pan/zoom/reset, node inspection, compact operator state, bounded observation logs and telemetry. Ambient particles are visual effects, not fabricated activity. Reduce Motion and scene inactivity stop continuous motion; static wiring does not continuously redraw.

Product Lab adds an on-device SceneKit preview, dimensions/material/process controls, optional model-assisted parameter suggestions, live basic conflict checks, generated-mesh viewing and STEP/STL/DXF/report sharing. The local preview is not an exact CAD export and omits mounting holes until the server mesh is generated. The installed VPS engine exports validated solids for three templates; other concepts require additional engineering. Candidate status does not establish physical performance. The Engine section reports SuperCraftOS's native capability policy and measured outcomes; researched external projects remain design references and are not silently installed or signed into.

Grant Ops displays official Ethereum, Gitcoin, Arbitrum and Optimism opportunities, payment cadence, evidence links and current-source caveats. The backend can screen a project and create a complete editable application packet. Submission can be invoked through a configured provider adapter only when the programme publishes an official JSON intake endpoint; the adapter enforces HTTPS and an exact official host, persists the provider receipt, and returns `unsupported` when no endpoint is configured. A prepared packet is never presented as a submission receipt.

Verification on this Linux VPS: the installed Swift 6.0.3 compiler parses the Swift source, and a separate package builds and tests the identical Foundation models/utilities through a CLI. The actual App Playground build and test commands fail because this toolchain has no AppleProductTypes module; SwiftUI is also unavailable. This archive has not been compiled or rendered by an Apple SDK. Open it in Swift Playgrounds for the remaining platform build check.

Tasks use the durable autonomous queue, including scheduled starts, retry/cancel, action explanations, command receipts, acceptance reviews, and completed-file sharing. Memory displays original execution practices and evidence-linked lessons from verified tasks; Forget removes a lesson from future retrieval. This is retrieval memory, not model-weight training. Quests exposes discovery, source failures, screening, configured actions and provider receipts. Missing provider adapters and wallet connections are reported, not simulated.

Rebuild the archive with `python scripts/package_ipad.py`. Run `swift test --package-path swift-verification` to test the identical Foundation networking/model code, and `swiftc -frontend -parse ios_app_dist/*.swift` for syntax validation. These are separate from the required Apple SDK build. No Mac was available in the workspace allocation, so Apple framework type-checking and rendering remain unverified.

Shortcuts includes Open Workspace, Send Agent Task, Check Task and Get Task Output. The in-app Shortcuts page opens Apple’s app actions. Send returns a tracking ID; after completion, Output returns a summary text file or a named, checksum-verified artifact for Notes/Files/other actions. See [Apple Shortcuts setup](../docs/APPLE_SHORTCUTS.md). App Intents metadata and device automation remain part of the Swift Playgrounds/Apple validation.
