# Executable tools and verified flows

The web console at `/agents` exposes every registered MCP tool in **Tools**. It submits the selected name and JSON arguments to authenticated `POST /api/tools/call`; the server validates the tool schema and executes the actual handler. The autonomous worker reads the same live tool registry for its available actions, so newly registered tools can be selected without editing an allowlist. Task details expose a bounded, redacted trace through `GET /api/jobs/{id}/trace`.

The provider-specific ingestion tools are `ingest_browserless`, `ingest_tavily`, and `ingest_firecrawl`. They require their respective server-side environment variables; none of the credentials are sent to the browser or stored in this repository. Their supported API surfaces are [Browserless Content](https://docs.browserless.io/rest-apis/content), [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search), and [Firecrawl Scrape](https://docs.firecrawl.dev/api-reference/endpoint/scrape). A successful request returns the provider response and status; it is not proof that every page or claim in the response is correct.

The web **Product Lab** screens a fixed-template design, runs the installed CadQuery/OpenCascade worker, verifies a single valid solid and a STEP round trip, and serves STEP, STL, DXF, and report files. The worker has a 384 MB RSS cap, and the controller plus children have a 512 MB cap. The geometry checks do not establish production manufacturability, load safety, regulatory compliance, or suitability for any specific printer or CNC machine.

The **Grant Ops** screen ranks the saved official-source catalog against a project profile and saves a structured application draft. It provides source links, evidence requirements, and a delivery plan. Catalog matches and drafts are not grant awards or submissions. Submission requires a configured and working program adapter and an actual acknowledgement from that program; the UI and API must report that separately. Tool-only agent tasks can finish after a successful native tool result and an independent acceptance review. Source-code tasks still require a plan, actual files, and a successful command check on the current files. The web task detail shows native tool results separately from shell checks.
